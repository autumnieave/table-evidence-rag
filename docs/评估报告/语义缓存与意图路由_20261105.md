## 0. 结论速览

| 项 | 结果 | 口径 |
| --- | --- | --- |
| 语义缓存是否原本存在 | **不存在**：原仓库只有 SQLite 精确缓存 + Redis 会话记忆 | 代码检索 |
| 同义问法命中率 | **5/5 = 100%**（整体 5/10 = 50%） | n=5 组，阈值 0.92 |
| 未命中 P50 / 均值 | **22,316.4ms / 17,880.9ms** | n=5，mode=rag |

| 加速比 | **P50 85.9×；均值 64.0×** | 同一批问题 |

一句话：**语义缓存对“同义改写”是数量级收益（22.3s → 0.26s），但当前只验证了 5 组、且默认关闭；意图路由在本批 10 条上两种口径都 10/10，n 小，只能作方向性结论。**

## 2. 实现与接线

| 文件 | 作用 |
| --- | --- |
| `src/utils/semantic_cache.py` | 语义缓存核心：Redis KV + zset 索引，进程内余弦相似度；内存回退；TTL / LRU 淘汰 / 统计 |
| `src/config/rag_config.py` | 新增 `SEMANTIC_CACHE_*` 配置（默认 `ENABLED=false`、阈值 0.92、TTL 24h、单 namespace 上限 1000） |
| `src/app/api.py` | `/chat` 在精确缓存之后、真实链路之前查语义缓存；命中直接回放；新增 `GET /cache/stats` |
| `tests/test_semantic_cache.py` | 7 条离线单测：相似度、命中、阈值拒绝、namespace 隔离、TTL、淘汰、清理 |

### 2.1 存储结构

- 索引：`semcache:{version}:{ns_hash}:index`（zset，score=写入时间）
- 条目：`semcache:{version}:{ns_hash}:entry:{sha1(question)}`（JSON：question / embedding / payload / created_at / expires_at）
- `namespace = "{mode}:{user_id}"`，按用户隔离，避免跨用户回放
- Redis 不可用时降级进程内字典，`stats().backend` 标注 `memory`

### 2.2 关键取舍

- **不依赖 Redis Stack 向量索引**：用 zset 取候选、进程内算余弦；实现简单，但每次 lookup 是 O(n)，当前 `max_entries=1000` 可接受，规模化需换 Redis Stack / 向量库。
- **同时接 `/chat` 与 `/chat/stream`**：流式命中按 `meta → content → done` 回放，不进入真实检索/生成；未命中在完成后写回缓存。
- **默认关闭**：语义缓存有“相似但不同问题”的误命中风险，必须显式开启。

## 4. 意图路由验证

### 4.1 当前路由逻辑（先梳理）

- **真实派发**：`LangGraphMultiAgentPlanner._supervisor` 由 LLM 拆子任务，任务带 `agent=financial|research`；`_route_after_supervisor` 据此走 `tools` 或 `finalize`。
- **兜底标记**：`_classify_route_type` 是关键词三分类（financial / research / mixed），**只用于 route_type 标记和空任务兜底，不改变图结构**。
- **财务兜底**：supervisor 无任务但命中财务关键词时，`_ensure_financial_task` 强制补一个 financial 任务。
- 不存在独立的“顶层意图路由器”组件；本次验证同时测了“关键词兜底”和“真实 supervisor 派发”两种口径。

## 6. 边界与风险（必须如实说明）

1. **样本小**：语义缓存 n=5 组（10 次请求），意图路由 n=10；均为单轮、单次运行，只能作方向性参考，不是统计显著结论。
2. **语义缓存默认关闭**：`SEMANTIC_CACHE_ENABLED=false`；本次通过环境变量显式开启。默认关是有意为之，避免“相似但不同年份/指标”的问题被错误回放。
3. **误命中风险未充分验证**：只测了 1 组不相关对照；需要 50–100 组“同义 / 非同类”标注对，画相似度分布后再定阈值。
4. **命中仍有成本**：免去 LLM 生成 Token（Completion），但保留一次极低成本的 query embedding（约 226ms）；embedding token 未计入统计（服务端未上报）。
5. **实现规模**：当前缓存匹配采用进程内 O(n) 余弦相似度，在缓存量 <1000 时性能可接受（约 226ms）；生产环境将替换为 RediSearch 或专用向量库索引，解决 O(n) 退化问题。
6. **流式已接入**：`/chat/stream` 在生成前查语义缓存，命中按 `meta → content → done` 回放；本次实测数据仍来自 `/chat` 非流式，流式 TTFT 收益未单列。
7. **意图路由不是独立组件**：真实分流依赖 supervisor LLM；关键词分类器只是兜底标记。10/10 是“这批题”的准确率，不代表开放分布。
8. **SQL 耗时含生成/分析**：8.3s 是 `call_financial_chatflow` 端到端（SQL 生成 + 编译 + 执行 + 分析），不是纯 MySQL 查询时间。
9. **未做 SQL 结果准确率校验**：按要求不做；S2/S5 的短回答只作为观察记录，不判定对错。

## 8. 建议

- **语义缓存**：保留为默认关闭的可选能力；先用 50–100 组标注对验证误命中率，再决定是否默认开启。当前数据足以支撑“同义改写可降一个数量级”的结论，不足以支撑“生产可开”。
- **意图路由**：本批 10/10，无需改代码；若要写进简历，建议表述为“关键词兜底 + supervisor 派发在 10 条标注集上 10/10”，并注明小样本。
- **下一步**：优先补“同义/非同类”标注集与阈值曲线；规模化时把 O(n) 扫描换成向量索引。
