# Redis 分布式限流与 LangGraph 状态外置 — 验收报告（2026-11-05）

> 分支：`feature/redis-infra`（未合并 master）
> 目标：把单进程限流换成多节点共享的 Redis 滑动窗口；把 LangGraph 会话状态从本机 SQLite 外置到 Redis，实现跨进程恢复。

## 一、结论

| 验收项 | 目标 | 实测 | 结论 |
|---|---|---|---|
| 50 并发下的限流正确性 | 超过阈值全部 429，且不超发 | 50 并发 → **20 通过 / 30 拦截 / 0 错误**，Redis `zcard=20` | 通过 |
| 429 响应契约 | 状态码 + `Retry-After` | 30 条 429 全部带 `Retry-After: 59–60` | 通过 |
| 分布式语义 | 窗口为多节点共享，不是进程内计数 | 另建限流器实例（新连接、同前缀）→ `allowed=False, retry=59.308s` | 通过 |
| 状态外置 | 多轮会话写入 Redis | 两轮 `/chat` 后该 `thread_id` 下 **59 个 key**（ReJSON-RL 48 / zset 10 / string 1） | 通过 |
| 跨实例恢复 | 新进程读回上一进程的上下文 | 真实 Planner `_load_memory()` 读回 **7 条消息 / 3 个 user turn**；空 thread 为 0 | 通过 |
| 降级路径 | Redis 不可用不阻断主流程 | 限流降级内存、checkpoint 降级 sqlite → memory，均有日志 | 通过 |
| 单测 | 全绿 | **1050 passed in 20.53s**（基线 1041，新增 9 条） | 通过 |

**未验证项（不作为结论）**：真实 API 多轮对话的**回答内容**。本次验证时本机 MySQL 未启动，两轮回答均为 `MySQL schema/连接加载失败` 的兜底话术。记忆效果改用运行时真正喂给 supervisor 的 `_load_memory()` 读回结果证明，**不等于“多轮回答质量已验证”**。

## 二、改了什么

| 层 | 改动 | 文件 |
|---|---|---|
| 限流核心 | zset + Lua 原子「清理 → 计数 → 写入」；`allow() -> (allowed, retry_after)`；异常降级内存并置 `degraded` | `src/utils/api_security.py` |
| 限流工厂 | `create_rate_limiter(backend=redis/memory)`，Redis 不可达回退内存 | `src/utils/api_security.py` |
| API 接线 | `/chat`、`/chat/stream`、`/chat/clarify` 按 `user_id` 限流；流式在 SSE 生成器**外**校验，避免 429 变成 SSE error 事件 | `src/app/api.py` |
| Checkpoint | `AGENT_LANGGRAPH_CHECKPOINT_BACKEND=redis` → 官方 `RedisSaver`，`thread_id=user_id`；失败降级 sqlite → memory | `src/agents/langgraph_planner.py`、`src/agents/langgraph_multi_agent.py` |
| 配置 | `API_RATE_LIMIT_BACKEND`（默认 redis）、`API_RATE_LIMIT_REDIS_URL`（`redis://localhost:6379/2`）、`USER_RATE_LIMIT_ENABLED`（默认 true）、`USER_RATE_LIMIT_PER_MINUTE`（默认 20）、`AGENT_LANGGRAPH_CHECKPOINT_REDIS_URL`（`redis://localhost:6380/0`） | `src/config/rag_config.py` |
| 依赖 | `langgraph-checkpoint-redis>=0.6.0`、`redis>=5.0.0` | `requirements.txt` |
| 脚本 | 50 并发压测（pipeline 桩化，不消耗 LLM） | `eval/rate_limit_bench.py` |

## 三、限流实测（50 并发）

配置：`USER_RATE_LIMIT_PER_MINUTE=20`，同一 `user_id`，`/chat`，pipeline 替换为即时返回桩对象（只压限流链路，不压 LLM）。

| 指标 | 值 |
|---|---|
| 并发数 | 50 |
| 200 通过 | **20** |
| 429 拦截 | **30** |
| 其他状态 / 连接错误 | 0 |
| 总墙钟耗时 | 812.4 ms |
| 成功请求 P50 / P95 | 470.4 / 544.7 ms |
| 429 请求 P50 / P95 | 607.8 / 617.1 ms |
| `Retry-After` 取值 | 59、60 秒 |
| Redis 窗口 `zcard` | **20** |
| 单请求基线（concurrency=1） | **21.4 ms** |

解读：

- 恰好 20 通过、30 拦截，说明 Lua 的“检查 + 写入”是原子的，50 个并发没有超发（不是 21 或 19）。
- 429 的 P50 608ms **不代表 Redis 调用成本**。单请求基线 21.4ms（其中桩业务 sleep 10ms），50 并发时新增的是 Windows loopback 上 50 条 TCP 连接的建立 + 事件循环/线程池排队。报告里不把它当“限流开销”。

## 四、Checkpoint 实测

环境：`redis/redis-stack-server`（6380，提供 RedisJSON + RediSearch），API 以 `AGENT_PLANNER_BACKEND=langgraph`、`AGENT_LANGGRAPH_MULTI_AGENT=true` 启动。

### 4.1 写入

同一 `user_id` 连发两轮 `mode=agent`：

| 轮次 | 问题 | HTTP | 耗时 | 回答 |
|---|---|---|---|---|
| 1 | 贵州茅台2024年营业收入是多少？ | 200 | 3.13s | MySQL 不可用兜底话术 |
| 2 | 那它的净利润呢？ | 200 | 0.70s | MySQL 不可用兜底话术 |

Redis 中该 `thread_id` 下的 key：

| 类型 | 数量 | 样例 |
|---|---|---|
| ReJSON-RL | 48 | `checkpoint:<thread_id>:__empty__:<checkpoint_id>` |
| zset | 10 | `write_keys_zset:<thread_id>:__empty__:<checkpoint_id>` |
| string | 1 | `checkpoint_latest:<thread_id>:__empty__` |

### 4.2 跨实例恢复

新进程（等价于另一节点）构造真实 `LangGraphMultiAgentPlanner`，用同一 `thread_id` 调 `_load_memory()`：

```
[replay] restored_messages=7 user_turns=3
  turn1: 贵州茅台2024年营业收入是多少？
  turn2: 那它的净利润呢？
  turn3: 我上一轮问的是哪家公司的哪个指标？
[replay] fresh_thread_messages=0
[replay] cross_instance_restore_ok=True
```

- 7 条消息包含 system + 3 个 user turn + 3 条 assistant/tool 消息；
- 不存在的 `thread_id` 读回 0 条，说明会话按 `user_id` 隔离，不串。

补充：单测 `test_redis_checkpoint_restores_across_instances` 用最小 StateGraph + 两个独立 `RedisSaver` 实例验证同一 thread 的计数 1→2（实例 A）→3（实例 B）。

## 五、降级行为

| 场景 | 行为 | 日志 |
|---|---|---|
| 启动时 Redis 不可达 | 返回内存限流器，服务正常启动 | `rate_limiter_redis_unavailable fallback=memory` |
| 运行中 Redis 报错 | 切内存窗口，`degraded=True` | `rate_limit_redis_failed fallback=memory` |
| Checkpoint Redis 初始化失败 | 降级 sqlite；sqlite 也失败则 memory | `LangGraph ... redis checkpoint 初始化失败，降级 sqlite` |

## 六、复现

## 七、边界

1. **Checkpoint 需要 Redis Stack**（RedisJSON + RediSearch）；普通 `redis:7` 只能跑限流，不能跑 checkpoint。
2. `RedisSaver` 未做并发写压测；本次只验证串行两轮 + 跨进程读。
3. 限流是固定阈值 + 60s 滑动窗口，没有突发桶、分级配额；`Retry-After` 取整到秒。
4. 50 并发是单机 loopback，不是生产网络压测，绝对延迟不可外推。
5. 每用户 20 req/min 是代码默认值，未做业务容量评估。
6. 多轮回答质量未验证（MySQL 未启动），只验证了状态写入与恢复。
