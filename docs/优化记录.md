## 7. 口径修正记录

### 2026-11-03：Faithfulness 三口径定义修正

此前交接文档曾写“Claim 级 Faithfulness 90.34%（22 题主口径）”，并称“99.38% 已废弃”。经代码与结果文件核对，该说法不成立，现更正为三口径并列：

| 口径 | 数值 | 分子 / 分母 | 计算方式 | 含义 |
|---|---|---|---|---|
| claim 级 micro | **98.36%** | 120 / 122 claims | 全部 claim 等权汇总 | 所有生成 claim 中被证据支持的比例 |
| 题均 macro（可评题） | **99.38%** | 19.875 / 20 题 | 每题 `support_rate` 等权平均，剔除 2 道 0-claim 题 | 有 claim 的题，平均支持率 |
| 22 题题均 macro（含 0-claim） | **90.34%** | 19.875 / 22 题 | 同上，但 0-claim 题记 0.0 | 全部 22 题的平均支持率 |

- 99.38% 与 90.34% 的分子相同（19.875），差异只在分母（20 vs 22）；90.34% **不是**“端到端可答率”，也不是二值准确率（19.875 非整数，不可能是“答对题数 / 22”）。
- 被剔除的 2 道 0-claim 题：`B2007|2`、`AEXP|03`；`AEXP|04` 虽为拒答但有 1 条 claim 且被支持，仍计入 20 题分母。
- CI 方法：percentile bootstrap，10,000 次，seed `20261018`；99.38% 的 CI 为 98.13–100，90.34% 的 CI 为 76.70–100。
- 证据文件：`训练结果数据/stage5_measure/faithfulness_a_expand_20plus_final.json` → `summary.combined`
- 汇总脚本：`训练结果数据/stage5_measure/_a_expand_finalize.py:24-31`（bootstrap）、`:124-130`（combined）
- 逐题计算：`src/core/claim_faithfulness.py:216-224`
- 结论：**99.38% 未废弃**，它是当前“20 道可评题”主口径；对外引用必须同时写明分母是 20 题而非 22 题。

- 代码：将 `AGENT_LANGGRAPH_CHECKPOINT_BACKEND` 置回 `sqlite`（env 覆盖即可，无需改代码）。
- 已写入 Redis 的 checkpoint 不影响 sqlite 回退路径。

### 13.6 局限

- Redis Stack 单节点，未配置密码与持久化高可用；生产需补 ACL、探活与哨兵/集群。
- 记忆后端当前仍为 sqlite；`MEMORY_REDIS_URL` 已统一为 `redis://redis:6379/0`，切换只需设 `MEMORY_BACKEND=redis`（宿主直跑时覆盖为 `redis://localhost:6379/0`）。

## 14. 端到端延迟 A/B 回归：Prompt 约束 / Semantic Cache / SSE（2026-11-06）

### 14.1 实验目的与固定条件

本轮只做**控制变量回归**：同一台机器、同一网络、同一 Qdrant/Redis、同一 10 题、同一 `qwen3.5-plus`，顺序请求，不并发。比较“无缓存同步生成”与“Prompt 约束 / Semantic Cache / SSE”四阶段差异。

固定条件：

- API：本地 `uvicorn app.api:app --app-dir src --port 8000`。
- Qdrant：`research_reports_v3_full`；Redis：项目内 `redis/redis-stack-server`。
- `QUERY_CACHE_ENABLED=false`（关闭 SQLite 精确结果缓存，避免旧结果干扰）。
- `USER_RATE_LIMIT_ENABLED=false`（避免 20 req/min 窗口影响延迟）。
- `OBSERVABILITY_LOG_ENABLED=true`；服务端 stage 耗时按 `X-Trace-Id` 从 `训练结果数据/logs/YYYYMMDD.jsonl` 回读。
- 每阶段开始前用一道**不在测试集内**的 Query 预热检索/精排/客户端，预热请求不计入统计。

### 14.2 Prompt 变量的真实口径

生产代码**没有独立的“精简输出”开关**，也没有强制字数上限。因此本轮没有伪造一个“精简模式”，而是使用可追溯的两个真实 Prompt 版本：

- **基线 Prompt**：当前生产模板去掉 2026-11-05 新增的第 9–11 条（多口径分句、禁止自算差值、不同来源分别标注），即 2026-10-18 版约束。
- **Prompt 阶段**：当前生产 `RAG_PROMPT_TEMPLATE`（2026-11-05-v1，含第 6–11 条证据约束），仍不设字数上限。

结论应表述为“2026-11-05 证据约束版的实测收益”，不能表述为“上线了独立的精简输出模式”。

### 14.5 Prompt 约束的配对收益

10 题逐题配对（基线 − Prompt，正数表示 Prompt 更快）：

- 总耗时：中位数 **−1,995.5 ms**（即 Prompt 快约 2.0 s），均值 **−2,059.1 ms**；10 题中 **7 题更快**。
- 输出字符：中位数 **−97.5 字**，均值 **−116.8 字**；10 题中 **7 题更短**。
- completion token：P50 从 661 降到 481.5，均值从 863.8 降到 809.6。

但收益不是均匀的：Q6 反而从 37,256.1 ms 升到 41,739.3 ms，输出从 2,467 字升到 2,948 字。原因是本次生成随机性导致 completion token 从 1,624 升到 1,975，**不是检索或网络退化**。

### 14.6 Q6 长尾归因与敏感性

Q6 是本轮唯一超过 40 s 的请求：

| 指标 | Q6 基线 | Q6 Prompt |
| --- | ---: | ---: |

### 14.7 Semantic Cache 命中结果

5 组同义改写全部命中，命中率 **5/5 = 100%**（相对总请求为 5/15 = 33.3%，因为另有 10 次首问 miss）：

| Pair | 相似度 | 命中总耗时 | 首字耗时 |
| --- | ---: | ---: | ---: |
| P1 | 0.932984 | 920.1 ms | 906.6 ms |
| P2 | 0.980272 | 1,696.0 ms | 1,663.0 ms |
| P3 | 0.959357 | 1,656.1 ms | 1,634.5 ms |
| P4 | 0.974033 | 1,056.4 ms | 1,055.4 ms |
| P5 | 0.967965 | 1,664.2 ms | 1,616.6 ms |
| **P50** | — | **1,656.1 ms** | **1,616.6 ms** |

- 相对基线 P50：20,504.3 / 1,656.1 = **12.4×**；相对 Prompt 同步 P50：15,254.0 / 1,656.1 = **9.2×**。
- 命中请求仍会调用 DashScope `text-embedding-v2` 生成 Query 向量，再做 Redis KV + 进程内 O(n) 余弦；当前网络下 embedding 往返使命中延迟高于历史文档中的 0.26 s。**1.66 s 是本轮真实值，不能与历史 0.26 s / 85.9× 混写。**
- 本组命中样本 n=5，按项目口径标注：**小样本，方向性参考**。

### 14.8 SSE 事件顺序与可观测性

- 冷启动（未命中）：`content → ... → meta → done`；首个 `content` 即 TTFT，`meta` 在生成完成、引用核验结束后才下发。
- 缓存命中：`meta → content → done`，无生成阶段。
- 本轮 10 次 SSE 首问均满足上述顺序；5 次缓存命中也均为 `meta` 先到。
- `/chat/stream` 响应头未返回 `X-Trace-Id`，因此本轮 SSE 的 stage/token 没有按 trace 强行回读；表中 SSE 仅报告客户端 TTFT/总耗时，**不估算 token**。

### 14.9 数据质量与局限

- 10/10 次基线、10/10 次 Prompt、10/10 次 SSE 首问均成功返回，无 429/500。
- 同步阶段 token 可用率 10/10；SSE 阶段未取得可对齐 trace，token 记为“未取到”，未填 0 或估算值。
- 语义缓存命中 n=5，属于小样本；延迟受 DashScope embedding 网络往返影响，生产环境应单独监控 embedding P95。
- 本轮为单机、顺序回放、本机 loopback，不是并发压测；P50 不代表线上 SLA。
- 本轮的 Prompt 基线使用实验性变体入口，仅为控制变量；生产代码仍只保留当前 `RAG_PROMPT_TEMPLATE`。
